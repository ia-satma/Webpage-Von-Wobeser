## 2. Arquitectura vigente

La plataforma convive en un solo servidor Express con cuatro superficies:

1. **Sitio público:** espejo HTML/Joomla versionado en `frontend-mirror/`, transformado en cada
   request por `server/mirror/` con Cheerio y datos PostgreSQL. No es una aplicación React.
2. **CMS:** SPA React 18 bajo `/admin/*`, con Wouter y TanStack Query.
3. **Backend:** Express + PostgreSQL + Drizzle ORM.
4. **Agentes:** 14 agentes canónicos, cola persistente, auditorías, conocimiento y medios
   generados.

### Orden crítico de arranque

`server/index.ts` debe conservar este orden:

1. registrar APIs con `registerRoutes`;
2. registrar el espejo con `setupMirror`;
3. registrar el manejador de errores;
4. registrar estáticos de producción o Vite en desarrollo;
5. escuchar el puerto y después iniciar agentes/schedulers.

`frontend-mirror/` es obligatorio. Si falta la plantilla guardia
`frontend-mirror/index.php/lawyer/l-134.html`, `setupMirror()` deshabilita las rutas públicas y el
catch-all de React termina enviando `/` al login administrativo. No borrar, mover ni “limpiar” el
espejo.

## 10. Seguridad y privacidad

- CSP obligatoria por respuesta con nonce criptográfico.
- `script-src-attr 'none'`; no se permite `unsafe-inline` ni `unsafe-eval` para scripts.
- SRI SHA-384 en assets locales fijos.
- HTML dinámico usa `private, no-store`; assets conservan caché larga.
- Sesión/challenge propios usan prefijos `__Host-`, `HttpOnly`, `Secure`, `SameSite=Strict` y
  `Path=/` en producción.
- La cookie `GAESA` observada es emitida por la infraestructura Google/Replit, no por la
  aplicación; debe reevaluarse en el dominio definitivo del cliente.
- Cargas se validan por contenido, tamaño y ruta; hay cuarentena y saneamiento de nombres.
- CV y documentos privados no se sirven desde `/uploads`.
- RBAC, CSRF/origen, rate limits, sesiones, auditoría de login y saneamiento están centralizados.
- Legal Alerts restringe fuentes por allowlist y evita SSRF.
- Dependencias con avisos altos detectados el 14-ago fueron actualizadas/encapsuladas y se añadió
  auditoría de suministro para CI.

## 13. Handoff a la cuenta Replit del cliente

GitHub transporta el código, pero no Secrets, PostgreSQL, App Storage ni documentos privados.
La entrega completa requiere:

1. repositorio;
2. respaldo PostgreSQL cifrado;
3. paquete verificado de medios públicos;
4. paquete cifrado de CV/documentos privados.

Flujo obligatorio en un Repl nuevo:

```bash
npm run handoff:status -- --directory=.handoff
npm run handoff:install -- \
  --directory=.handoff \
  --confirm-database=<base-nueva> \
  --confirm-owner-email=<correo-del-cliente>
```

- `start:workspace` y `start:deploy` detectan una base nueva y muestran una pantalla de
  instalación pendiente en lugar de fallar con `500`.
- El instalador sólo escribe sobre una Database vacía y exige confirmar base y Dueño.
- Secrets se configuran en Replit Tools → Secrets. Nunca se pegan en Shell, chat, Git o capturas.
- App Storage y Database deben pertenecer a la cuenta nueva del cliente.
- Consultar [`CLIENT_REPLIT_HANDOFF.md`](CLIENT_REPLIT_HANDOFF.md) antes de una entrega.
