## Reglas y flujo de Replit

1. Confirmar conexión Git sin alterar archivos:

   ```sh
   git remote get-url origin && git ls-remote origin HEAD
   ```

2. En un workspace de Replit ya instalado, conservar cambios locales generados y actualizar:

   ```sh
   git stash push -u -m "replit-local-before-<sha>" && git pull --rebase origin main && npm run db:migrate && npm run build
   ```

3. Si `git pull --rebase` informa cambios no guardados, inspeccionar `git status --short`. Incluir
   `.replit` y archivos generados por Replit en el stash; no hacer `reset --hard`, no borrar el
   workspace y no añadir credenciales al remoto.
4. Si Preview muestra “Instalación del cliente pendiente”, entender que no tiene datos ni App
   Storage. No es una regresión pública, pero tampoco es una validación visual de datos reales.
5. Tras pull, migración y build correctos, el operador puede realizar Publishing desde Replit.
   Confirmar el SHA y la salud del sitio publicado después del Promote.
